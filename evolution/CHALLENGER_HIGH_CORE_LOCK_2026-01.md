# Challenger: High-Core Crowding Lock

## Scope

This Challenger changes one upstream rule in `SKILL.md`: when a 7-or-more
board highest core coexists with broad negative feedback and high limit-break /
limit-down counts, the highest core cannot automatically become the formal
queue head. A mainline low-position candidate may replace it only when it
passes the explicit low-position and response gates; otherwise the result is
waiting/empty.

The auction rule and return protocol are unchanged.

## Paired Replay

The full 19-case January development window was regenerated by
`run_high_core_lock_challenger.py`. The canonical baseline decisions table was
used to preserve empty and unverifiable states. No T+2 return was used to
construct the Challenger decision.

The metric improvement is driven by two dates:

  `-10.021946%`.

All other cases preserve their canonical execution state and return path.

## Review Gate

Resource constraint: the review was run in one local process with no spawned
judge agents because the machine previously reached CPU saturation. The
review is therefore a paired, rubric-scoped manual gate, not independent
multi-agent evidence.

- Chain fidelity: pass. The output contains all 19 dates and regenerates the
  downstream queue, auction decision, execution state, and return fields.
- Leakage: pass. The trigger uses only T-day fields; T+2 outcomes appear only
  in the comparison report.
- Economic development result: pass. The Challenger improves the development
  window without changing the auction or return formula.
- Generalization risk: unresolved. The rule has only two trigger examples in
  this development window and has not been tested on the sealed
  2026-09-01 to 2026-10-09 validation set.

## Decision

`provisional_keep_for_development`.

This Challenger is eligible for the next development round, but it is not a
final production acceptance. The next round must audit whether the lock is
too broad, especially whether it incorrectly blocks a genuinely strong
high-core continuation in another market regime. The sealed validation set
remains untouched until the first-round environment, sentiment, mode,
mainline, node, candidate, and execution audits are complete.
